# API Contract

This document describes the alpha API contract between the frontend app and the NestJS API.

## Response Envelope

All JSON success responses must use the same envelope:

```json
{
  "success": true,
  "data": {},
  "meta": {},
  "requestId": "request-id",
  "correlationId": "optional-correlation-id",
  "path": "/endpoint",
  "timestamp": "2026-09-09T00:00:00.000Z",
  "version": "optional-api-version"
}
```

Rules:

- `success` is always `true` for successful JSON responses.
- `data` contains the useful payload.
- `meta` is optional and reserved for pagination or transport metadata.
- `requestId` is copied from the `X-Request-ID` request header.
- `path` is the requested URL.
- `timestamp` is generated by the API.
- The frontend should use `requestPayload<T>()` when it only needs `data`.
- The frontend should use `requestEnvelope<T>()` when it needs transport fields or wants to inspect errors directly.

## Error Response

All JSON errors are normalized as Problem Details:

```json
{
  "type": "",
  "title": "Bad Request",
  "status": 400,
  "detail": "Human-readable details",
  "code": "400",
  "errors": [],
  "requestId": "request-id",
  "instance": "/endpoint",
  "timestamp": "2026-09-09T00:00:00.000Z"
}
```

Rules:

- Controllers should throw Nest `HttpException` classes instead of returning error-like success payloads.
- Field-level validation errors belong in `errors`.
- The frontend should use `isApiError()` before reading error fields.

## Parameters

Use camelCase names for all API transport parameters.

Examples:

- `projectId`
- `languageId`
- `itemsPerPage`
- `sortDirection`
- `searchParams`
- `formatSettings`
- `caseSensitive`
- `inKeys`
- `inValues`
- `inFolders`
- `inComponents`

Rules:

- `GET` requests use query parameters for filters, ids, and read options.
- `POST` requests use JSON body for creation, updates, commands, and form submissions.
- `DELETE` requests use JSON body for destructive operations that require more than a simple URL route.
- Do not add new snake_case transport fields.
- Do not reintroduce legacy aliases unless a migration explicitly requires it.

## Auth And Sessions

Rules:

- The authenticated user id comes from the server-side session via `@CurrentUserId()`.
- The frontend must not send `userId` for user-owned resources.
- Protected endpoints must use `AuthGuard`.
- Session cookies are HTTP-only.
- Password reset and email verification flows use dedicated token DTOs.

## File Responses

Export endpoints are the exception to the JSON envelope rule.

Rules:

- `GET /exportProject` returns a zip blob directly.
- The frontend should call it through `apiClient` with `responseType: 'blob'`.
- Import endpoints return the standard JSON envelope.

## Current Alpha Compatibility

The alpha frontend and backend use the same primary transport contract:

- success responses are JSON envelopes;
- errors are Problem Details;
- query/body parameter names are camelCase;
- exports are raw file responses;
- imports are standard JSON envelope responses.
